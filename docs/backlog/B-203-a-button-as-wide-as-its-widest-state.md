# B-203 — A button as wide as its widest state

A button with no width grows 32 dp on Success (the check) and its body regenerates (F-buttons-04). [B-168](B-168-look-and-motion-pass.md)'s designer's answers, answer 35 ([ошибка]).

- **The decision and its reason.** Its width is the widest of all its states, measured once and kept, so no state change moves it. A new label is a new measurement.

- AC:
  - a button without a width keeps its width to the dp through rest, pressed, loading, Success and disabled, and its body is not regenerated by the state change *(rewritten: `MutantButtonState` has no Error; the AC named it from the answer's «all states»)*
  - a fixed width still wins
  - each new test fails on the code before and kills a mutant after the commit, but for the fixed-width guard, which held before as it must *(rewritten: a guard of a behaviour the change keeps cannot fail on the code before)*; goldens and parity cells at rest unchanged, or the moved ones listed with this item and looked at
- Anchors: `mutant-core/src/commonMain/kotlin/io/github/youndie/mutant/components/MutantButton.kt`

## Result, 2026-11-23

**The change.** `MutantButton` without an icon of the caller's tells `ButtonBody` that Success will add the check
(`checkRoom`). In every state where the check is not drawn, the content keeps its room: a layout modifier on the content
row (`buttonRoom`) asks the row's own intrinsic width, adds the check and its gap (24 + 8 dp, `BUTTON_ICON_SIZE`,
`ICON_GAP`), coerces it into the surface's constraints and lays the row out at least that wide, the label centred. So the
width is the widest state's in every state, at rest, pressed, loading, Success and disabled, to the pixel at any density:
Success's row is the same three widths summed. The body's slot keeps its size, so no state change regenerates it under
D17; Success still rebuilds its instance for the still frame and the clean zone around the check, as at a fixed width,
with the same shape and drips. The widest state is measured from the content, so a new label (or a new icon) is a new
measurement; a caller's width, or a parent's limit, wins through the coercion. The outlined and text buttons have no
state that adds anything and are untouched. Research D15 names the number with this item.

Rejected: never shrinking below the widest width shown (the finding's third option): the first Success would still grow
the button and regenerate its body, which the answer forbids; and remembering a measured width across compositions,
which a label change would have to invalidate by hand, where the intrinsic gives the same number every pass.

**Numbers.** «Воспроизвести» at density 1: 164 dp at rest and 196 dp on Success before; 196 dp throughout after. A button
with no width is 32 dp wider at rest than before.

**The sample.** The Foundations Theme cell's row (button and chip in 258 dp) was short of the 32 dp in Russian: the chip
«Шум» was squeezed to a body without its word. The button there now takes `weight(1f, fill = false)` and gives way;
looked at in both languages. The settings timer's row (time picker 181 dp + «Готово» 130 dp) still fits its sheet.
Every other width-less button in the sample stands alone in its cell, stage or sheet row.

**Tests** (`ButtonWidestStateTest`):

- `a button given no width keeps its width to the pixel through every state, at any density` — densities 1 and 2, font
  scale 1.5, with and without the caller's icon; the width equals the check, its gap, the label and the padding; a
  longer label is wider and kept in its turn, and the first label measures as before. Before the change:
  `{rest=164, pressed=164, loading=164, success=196, …}`.
- `a button given no width keeps one body through every state` — through the surface's probe: the body's slot keeps its
  width and height, and its shape and drips are the same between bodies of one wear (the press focuses the button, and
  focus calms the wear to 0.3, which reshapes it as at a fixed width). Before: `expected 164.0 but was 196.0` on Success.
- `a width from the caller still wins, narrower or wider than the widest state` — 120 and 260 dp at densities 1 and 2,
  the label inside and centred; a guard, green before as after.

**Goldens and parity.** No golden, parity cell or reference moved: every one draws the button at the design's fixed
widths (200 and 160 dp). The whole `./gradlew check` ran green on the kit's suites.

**Not verified.** No phone, adb or browser: the width is layout, the same code on every target, compiled for iOS.
